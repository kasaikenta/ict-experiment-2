Polarization とポーラ符号の理論解説

1. 元チャネル \(W\) と拡張チャネル \(W_N\)

2 値入力の離散メモリレス通信路 \[ W : \{0,1\} \to \mathcal{Y} \] を考えます。条件付き分布は \[ W(y\mid x),\quad x\in\{0,1\},\, y\in\mathcal{Y} \] で与えられます。

ブロック長 \(N = 2^n\) をとり、入力ビット列 \[ u^N = (u_0,\dots,u_{N-1}) \in \{0,1\}^N \] から送信ビット列 \[ x^N = (x_0,\dots,x_{N-1}) \in \{0,1\}^N \] を線形変換 \[ x^N = u^N G_N \] で生成します（演算は \(\mathbb{F}_2\) 上）。標準的には \[ G_N = B_N F^{\otimes n},\quad F = \begin{pmatrix}1 & 0\\ 1 & 1\end{pmatrix} \] を用いた Arıkan の極性変換行列を使います。

各成分 \(x_j\) を独立にチャネル \(W\) に通すと、ブロック長 \(N\) の拡張チャネル \[ W_N : \{0,1\}^N \to \mathcal{Y}^N \] が得られ、その条件付き分布は \[ W_N(y^N \mid x^N) = \prod_{j=0}^{N-1} W(y_j \mid x_j) \] となります。

2. 合成通信路（ビットチャネル） \(W_N^{(i)}\) の定義

情報ビット列 \(u^N\) を一様分布から取り、 \(x^N = u^N G_N\) に変換して送信する系を考えます。 このとき \((u^N, y^N)\) の同時分布は \[ P(u^N=u^N_0, y^N=y^N_0) = 2^{-N} \, W_N\bigl(y^N_0 \mid x^N_0\bigr), \] \[ x^N_0 = u^N_0 G_N \] で与えられます。

SC デコーダは、ビット \(u_i\) を推定するときに 受信ベクトル \(y^N\) と、すでに推定済みのビット \[ u_0^{i-1} = (u_0,\dots,u_{i-1}) \] にだけアクセスできると仮定します。

このとき、i 番目の合成通信路（ビットチャネル）を \[ W_N^{(i)} : \{0,1\} \to \mathcal{Y}^N \times \{0,1\}^{i-1} \] と定義し、条件付き分布を \[ W_N^{(i)}(y^N, u_0^{i-1} \mid u_i) = \sum_{u_{i+1}^{N-1} \in \{0,1\}^{N-i-1}} \frac{1}{2^{N-1}}\, W_N\bigl(y^N \mid x^N(u^N)\bigr) \] で与えます。ここで \[ u^N = (u_0,\dots,u_{i-1},u_i,u_{i+1},\dots,u_{N-1}), \quad x^N(u^N) = u^N G_N \] です。

意味としては、「入力ビット \(u_i\) を 0/1 のどちらかに固定し、 残りのビット \((u_0^{i-1}, u_{i+1}^{N-1})\) を一様ランダムに動かしたときに 観測される \((y^N, u_0^{i-1})\) の分布」が 1 ビットの通信路 \(W_N^{(i)}\) になっている、という定義です。 SC 復号はまさに、この 1 ビット通信路列に対して順番に判定を行う操作と解釈できます。

3. Polarization と容量

各ビットチャネルの相互情報量を \[ I\bigl(W_N^{(i)}\bigr) = I\bigl(U_i; Y^N, U_0^{i-1}\bigr) \] とおくと、Arıkan の Polarization 定理は概ね次を主張します。

多くの \(I(W_N^{(i)})\) は 0 か 1 のどちらかに近づき、 1 に近い「良い」ビットチャネルの割合は元のチャネルの容量 \(C(W)\) に収束する。

BEC(\(\varepsilon\)) の場合は \(C(W) = 1 - \varepsilon\) なので、 \(N\) を大きくしていくと、\(Z_i\) が 0 に近いビットチャネルの割合が 約 \(1 - \varepsilon\) になることが期待されます。 上のヒストグラムでは、\(n\) を増やすにつれて Z の分布が 0 と 1 の両端に集まり、中央付近が減っていく様子（分極）が観察できます。

4. 合成通信路を用いたポーラ符号の構成

ポーラ符号は、「どの合成通信路 \(W_N^{(i)}\) を情報ビット用に使い、 どの合成通信路を凍結（frozen）ビット用に使うか」を決めることで構成されます。 手順はおおまかに次の通りです。

  1. ブロック長 \(N = 2^n\) と情報ビット長 \(K\) を決め、元のチャネル \(W\) を固定する。
  2. 各 i について合成通信路 \(W_N^{(i)}\) の品質を評価する。 厳密には相互情報量 \(I(W_N^{(i)})\) を使うが、実装では Bhattacharyya パラメータ \(Z_i\) を用いて 「小さい \(Z_i\) ほど良い」とみなすことが多い（BEC では特に簡単）。
  3. \(Z_i\) が小さい（あるいは \(I(W_N^{(i)})\) が大きい）順に K 個のインデックス集合 \[ \mathcal{A} \subset \{0,\dots,N-1\},\quad |\mathcal{A}| = K \] を選ぶ。ここが情報ビットを入れる位置（良いビットチャネル）。
  4. 補集合 \(\mathcal{A}^c\) に属するインデックスは凍結ビットとし、 例えばすべて 0 に固定する： \[ u_i = 0,\quad i\in\mathcal{A}^c. \]

こうして得られる線形符号の集合は \[ \mathcal{C} = \Bigl\{ x^N = u^N G_N : u_i\in\{0,1\} \ (i\in\mathcal{A}),\; u_i = 0\ (i\in\mathcal{A}^c) \Bigr\} \] と書けます。すなわち、\(\mathcal{A}\) の位置にだけ情報ビットを詰め、 それ以外は既知の凍結ビットとして扱うことで、 「良いビットチャネルのみを使う符号」を構成しているわけです。

5. 符号化法（Encoding）

与えられた情報ビット列 \[ m = (m_1,\dots,m_K) \in \{0,1\}^K \] をポーラ符号で送るとき、次のように符号化します。

  1. 長さ \(N\) のベクトル \(u^N\) を用意する。 良いチャネルのインデックス集合を \(\mathcal{A} = \{i_1,\dots,i_K\}\) とすると、 \[ u_{i_j} = m_j,\quad j=1,\dots,K \] とし、 \[ u_i = 0,\quad i\in\mathcal{A}^c \] とする（ここでは凍結ビットをすべて 0 に固定した例）。
  2. 線形変換 \[ x^N = u^N G_N \] を計算して送信ビット列 \(x^N\) を得る。 実装上は、行列積をそのまま計算するのではなく、ファクターグラフに沿った バタフライ演算（XOR の木）として計算すると、 計算量 \(O(N\log N)\) で効率的に符号化できる。
  3. 得られた \(x^N\) をメモリレスチャネル \(W\) に入力し、受信側では \(y^N\) が観測される。

6. 復号法（Decoding）― SC 復号

最も基本的な復号法は「逐次キャンセル復号（Successive Cancellation, SC）」です。 SC 復号は、合成通信路 \(W_N^{(i)}\) の定義に沿って ビットを 1 つずつ順番に推定していきます。

  1. 受信ベクトル \(y^N\) が与えられたとする。 復号器は \(i = 0,1,\dots,N-1\) の順に \(u_i\) を推定する。
  2. もし \(i \in \mathcal{A}^c\)（凍結ビット）であれば、 送信側と約束された値（例：0）をそのまま \(\hat{u}_i\) として採用する。
  3. もし \(i \in \mathcal{A}\)（情報ビット）であれば、 合成通信路 \(W_N^{(i)}\) に対する対数尤度比 \[ L_i = \log \frac{ P\bigl(Y^N=y^N, U_0^{i-1}=\hat{u}_0^{i-1} \mid U_i=0\bigr) }{ P\bigl(Y^N=y^N, U_0^{i-1}=\hat{u}_0^{i-1} \mid U_i=1\bigr) } \] を計算し、しきい値判定 \[ \hat{u}_i = \begin{cases} 0, & L_i \ge 0,\\ 1, & L_i < 0 \end{cases} \] を行う。 実装では、ファクターグラフ構造を用いて LLR を効率的に更新することで、 全体として \(O(N\log N)\) の計算量で復号できる。
  4. 最終的に \(\hat{u}^N\) が得られたら、 \(\mathcal{A}\) の位置に対応するビット \(\hat{u}_{i_1},\dots,\hat{u}_{i_K}\) を取り出して 復号メッセージ \(\hat{m}\) とする。

下の SC 復号可視化セクションでは、この「i を 0 から順に走査する」という流れを 小さなブロック長 \(N = 2^{n_{\mathrm{SC}}}\) についてグラフィカルに見られるようにしてあります。
